# Лог интервью Grill Me: MILEAGE

Задача: «добавить в расчёт решения по заявке проверку — пробег авто не больше
400 000 км, иначе решение review».

Формат: режим Grill Me — агент задаёт вопросы по одному (не больше шести),
только те, от ответа на которые зависит реализация. Дата: 2026-09-30.
Заказчик: человек. Агент: Kilo (planner).

## Что сверил агент до вопросов

- порог кладётся в `rules.php`, блок `vehicle`, рядом с `max_mileage_km`;
- жёсткий потолок 500 000 км в `ApplicationValidator` остаётся как есть;

## Итог интервью

1. Правило — мягкое понижение `approve → review` при пробеге строго больше
   400 000 км; `review`/`reject` по LTV не перекрывает.
2. Полная шкала по пробегу: 0–400 000 → решение по LTV; 400 001–500 000 →
   review (даже если LTV давал approve); > 500 000 → 422 (существующий жёсткий
   потолок `max_mileage_km`).
3. Пробег обязателен: отсутствие/null → 422; `''` → 0 км — существующее
   поведение нормализации, сознательно не меняем.
4. Контракт ответа API не меняется: поле `reason` не добавляем.
5. Порог единый для всех заявок, источник значения — `rules.php`.

Ответы заказчика совпали с дефолтами `docs/plan/plan_MILEAGE.md` (раздел
«Вопросы, на которые без заказчика не ответить», вопросы 1–5) — расхождений
с планом нет, план актуален.
