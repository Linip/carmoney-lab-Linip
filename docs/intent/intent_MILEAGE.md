# Intent: правило «пробег не больше 400 000 км, иначе решение review» (MILEAGE)

Формулировка задачи от заказчика: «добавить в расчёт решения по заявке проверку —
пробег авто не больше 400 000 км, иначе решение review». Лог интервью:
`docs/intent/grill_MILEAGE.md`.

## 1. Замысел

Сегодня решение по заявке (`approve` / `review` / `reject`) вычисляется только
по LTV (код: `backend/src/Domain/DecisionEngine.php`); пробег проверяется лишь
на допустимость и на решение не влияет (код: `backend/src/Domain/ApplicationValidator.php`).

Добавляем в расчёт решения проверку пробега: если пробег авто больше 400 000 км,
решение по заявке — `review`. Новые входные данные не нужны: пробег уже входит
в заявку (код: `backend/src/Domain/ApplicationValidator.php`).

## 2. Зачем

Сегодня LTV может одобрить заявку с любым допустимым пробегом: например, при
низком LTV заявка с пробегом 450 000 получает `approve` — решение «не видит»
пробег (код: `backend/src/Domain/DecisionEngine.php`). Задача — чтобы высокий
пробег не позволял заявке получить автоматическое одобрение: такие заявки
должны уходить в `review` (формулировка задачи заказчика, подтверждено
ответами в интервью).

## 3. Constraints

| # | Ограничение | Источник |
|---|---|---|
| 1 | Порог 400 000 км, граница включительная: ровно 400 000 км — ещё `approve`; понижение — при пробеге строго больше 400 000 | ответ в интервью (вопрос 2) |
| 2 | Правило только понижает `approve` → `review`; `review` и `reject`, уже выданные по LTV, не меняются | ответ в интервью (вопрос 1) |
| 3 | Итоговая шкала по пробегу: 0–400 000 — решение по LTV; 400 001–500 000 — `review`; выше 500 000 — заявка отклоняется валидацией с HTTP 422 | 400 000 и понижение до review — ответ в интервью (вопросы 1–2); потолок 500 000 — код: `backend/config/rules.php`; статус 422 — код: `backend/src/Http/ApplicationController.php` |
| 4 | Пробег обязателен: отсутствие поля `mileage` или null — заявка отклоняется валидацией (HTTP 422), до расчёта решения не доходит | ответ в интервью (вопрос 3); текущее поведение — код: `backend/src/Domain/ApplicationValidator.php` |
| 5 | Пустая строка пробега трактуется как 0 км — существующее поведение, сохраняется | ответ в интервью (вопрос 4); код: `backend/src/Domain/ApplicationValidator.php` |
| 6 | Порог единый для всех заявок: не зависит от возраста, стоимости и других параметров авто | ответ в интервью (вопрос 6) |
| 7 | Причина `review` в ответе API не указывается: пониженное из-за пробега `review` неотличимо от `review` по LTV | ответ в интервью (вопрос 5) |
| 8 | Лимит в ответе при `review` — 0, ненулевой лимит только у `approve`; относится и к заявкам, пониженным из-за пробега | код: `backend/src/Domain/AssessmentService.php` |
| 9 | Расчёт LTV и его пороги не меняются: правило добавляется к решению по LTV, сам расчёт не затрагивает | ответ в интервью (вопрос 1); код: `backend/src/Domain/LtvCalculator.php` |

Сверка с исходной формулировкой: «не больше 400 000 км» = ≤ 400 000 —
совпадает с constraint 1. Единственное расхождение — «иначе решение review»
(буквально — «любое решение становится review», включая reject) против
constraint 2; снято самим заказчиком в интервью, зафиксировано в Open questions.

## 4. Open questions

| Вопрос | Статус |
|---|---|
| Формулировка «иначе решение review» буквально допускает «любое решение (включая reject) становится review» — расходится с constraint 2. Решение: только понижение `approve` → `review` | закрыт: заказчик, интервью (вопрос 1) |
| Ровно 400 000 км — `approve` или `review`? | закрыт: заказчик, интервью (вопрос 2) — `approve`, граница включительная |
| Пробег не указан (нет ключа / null) — оставить 422? | закрыт: заказчик, интервью (вопрос 3) — 422, валидацию пробега не меняем |
| Пустая строка `''` → 0 км — оставить? | закрыт: заказчик, интервью (вопрос 4) — оставить |
| Причина `review` в ответе API — нужна? | закрыт: заказчик, интервью (вопрос 5) — без причины |
| Порог единый или зависит от возраста/стоимости? | закрыт: заказчик, интервью (вопрос 6) — единый |

Открытых вопросов нет.

## 5. Не входит

- Изменение существующей валидации пробега: жёсткий потолок 500 000 км, тексты
  ошибок, обработка пустой строки (ответ в интервью, вопросы 3–4).
- Поле причины `review` в ответе API и правки фронтенда (ответ в интервью, вопрос 5).
- Дифференциация порога по возрасту или стоимости авто (ответ в интервью, вопрос 6).
- Влияние пробега на расчёт LTV (код: `backend/src/Domain/LtvCalculator.php`).
- Задача LOAN-12 — лимит по возрасту авто (код: `backend/config/rules.php`,
  комментарий блока `ltv_by_age`).
