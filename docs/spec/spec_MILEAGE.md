# Spec: правило «пробег не больше 400 000 км, иначе решение review» (MILEAGE)

Основание: `docs/intent/intent_MILEAGE.md`; все его Open questions закрыты интервью
`docs/intent/grill_MILEAGE.md`. Формулировка заказчика: «добавить в расчёт решения
по заявке проверку — пробег авто не больше 400 000 км, иначе решение review».

Контекст: решение (`approve` / `review` / `reject`) сейчас вычисляется только по LTV
(код: `backend/src/Domain/DecisionEngine.php`); пробег проверяется лишь на допустимость
и на решение не влияет (код: `backend/src/Domain/ApplicationValidator.php`). Новые
входные данные не вводятся: пробег уже входит в заявку.

## 1. Входит / не входит

### Входит

| # | Что входит | Источник |
|---|---|---|
| 1 | Проверка пробега в расчёте решения: при пробеге строго больше 400 000 км решение approve, вычисленное по LTV, понижается до review; при 400 000 км и меньше решение определяется LTV | интервью, вопросы 1–2 |
| 2 | Итоговая шкала по пробегу: 0–400 000 — решение по LTV; 400 001–500 000 — approve невозможен (понижается до review); выше 500 000 — отказ валидации с HTTP 422 | интервью, вопросы 1–2; код: `backend/config/rules.php`; код: `backend/src/Http/ApplicationController.php` |
| 3 | Существующее поведение ввода пробега без изменений: отсутствие поля или null — HTTP 422; пустая строка — 0 км | интервью, вопросы 3–4 |
| 4 | approved_limit = 0 у заявок, пониженных до review из-за пробега | код: `backend/src/Domain/AssessmentService.php` |
| 5 | Единый порог 400 000 км для всех заявок; значение хранится в справочнике правил | интервью, вопрос 6 |

### Не входит

- Изменение существующей валидации пробега: жёсткий потолок 500 000 км, тексты
  ошибок, обработка пустой строки (интервью, вопросы 3–4).
- Поле причины review в ответе API и правки фронтенда (интервью, вопрос 5).
- Дифференциация порога по возрасту или стоимости авто (интервью, вопрос 6).
- Влияние пробега на расчёт LTV (код: `backend/src/Domain/LtvCalculator.php`).
- Задача LOAN-12 — лимит по возрасту авто (код: `backend/config/rules.php`,
  комментарий блока `ltv_by_age`).

Раздел «Не входит» перенесён из intent без изменений.

| REQ-MILEAGE-03 | При пробеге строго больше 400 000 км решения review и reject, вычисленные по LTV, не изменяются | интервью, вопрос 1; intent, constraint 2 |

| REQ-MILEAGE-08 | Ответ API не содержит причину решения: пониженное из-за пробега review неотличимо от review по LTV; контракт ответа не меняется | интервью, вопрос 5; код: `backend/src/Http/ApplicationController.php`; intent, constraint 7 |
| REQ-MILEAGE-09 | Порог 400 000 км един для всех заявок: не зависит от возраста, оценочной стоимости и других параметров автомобиля | интервью, вопрос 6; intent, constraint 6 |
| REQ-MILEAGE-10 | Расчёт LTV и его пороги (`approve_max`, `review_max`) не изменяются | интервью, вопрос 1; код: `backend/src/Domain/LtvCalculator.php`; intent, constraint 9 |

## 3. Критерии приёмки

Формат Given / When / Then. «Валидная заявка» — заявка, проходящая существующую
валидацию, кроме случая, который проверяет критерий. Зоны LTV в примерах: 50 % —
approve, 75 % — review, 95 % — reject (пороги 60.0 и 85.0 — код:
`backend/config/rules.php`, блок `ltv`). Источники всех чисел — в таблице после списка.

- **AC-MILEAGE-01** (REQ-MILEAGE-01). Given: валидная заявка, LTV 50 %, пробег
  399 999 км. When: заявка оценивается. Then: decision = approve.
- **AC-MILEAGE-02** (REQ-MILEAGE-01). Given: валидная заявка, LTV 50 %, пробег
  400 000 км — ровно порог. When: заявка оценивается. Then: decision = approve —
  граница включительная.
- **AC-MILEAGE-03** (REQ-MILEAGE-01). Given: валидная заявка, LTV 75 %, пробег
  400 000 км. When: заявка оценивается. Then: decision = review — на пороге и ниже
  решение определяется LTV.
- **AC-MILEAGE-04** (REQ-MILEAGE-02). Given: валидная заявка, LTV 50 %, пробег
  400 001 км — первое значение за порогом. When: заявка оценивается.
  Then: decision = review.
- **AC-MILEAGE-05** (REQ-MILEAGE-03). Given: валидная заявка, LTV 75 % (review по
  LTV), пробег 450 000 км. When: заявка оценивается. Then: decision = review —
  не изменилось.
- **AC-MILEAGE-06** (REQ-MILEAGE-03). Given: валидная заявка, LTV 95 % (reject по
  LTV), пробег 450 000 км. When: заявка оценивается. Then: decision = reject —
  правило не отменяет reject.
- **AC-MILEAGE-07** (REQ-MILEAGE-02, REQ-MILEAGE-04). Given: валидная заявка,
  LTV 50 %, пробег 500 000 км — ровно жёсткий потолок. When: заявка оценивается.
  Then: валидация проходит (потолок 500 000 не сдвинут до 400 000),
  decision = review.
- **AC-MILEAGE-08** (REQ-MILEAGE-04). Given: заявка с пробегом 500 001 км.
  When: заявка оценивается. Then: HTTP 422, ошибка по полю `mileage`, решение
  не рассчитывается.
- **AC-MILEAGE-09** (REQ-MILEAGE-05). Given: заявка без ключа `mileage`.
  When: заявка оценивается. Then: HTTP 422, ошибка по полю `mileage`, расчёт
  решения не выполняется.
- **AC-MILEAGE-10** (REQ-MILEAGE-05). Given: заявка с `mileage` = null.
  When: заявка оценивается. Then: HTTP 422, ошибка по полю `mileage` — null
  трактуется как отсутствие поля.
- **AC-MILEAGE-11** (REQ-MILEAGE-06). Given: заявка с `mileage` = '' (пустая
  строка), LTV 50 %. When: заявка оценивается. Then: валидация проходит, пробег
  трактуется как 0 км, decision = approve.
- **AC-MILEAGE-12** (REQ-MILEAGE-07). Given: валидная заявка, LTV 50 %, пробег
  400 000 км, итоговое решение approve. When: ответ сформирован.
  Then: approved_limit = запрошенной сумме.
- **AC-MILEAGE-13** (REQ-MILEAGE-07). Given: валидная заявка, LTV 50 %, пробег
  400 001 км, решение понижено до review. When: ответ сформирован.
  Then: approved_limit = 0.
- **AC-MILEAGE-14** (REQ-MILEAGE-08). Given: две заявки с итоговым review: первая
  понижена из-за пробега (LTV 50 %, пробег 400 001 км), вторая — review по LTV
  (LTV 75 %, пробег 400 000 км). When: сформированы оба ответа. Then: наборы полей
  ответов совпадают; поля с причиной решения нет ни в одном.
- **AC-MILEAGE-15** (REQ-MILEAGE-09). Given: две валидные заявки, LTV 50 %, пробег
  400 001 км; возраст авто 2 года и 15 лет. When: заявки оцениваются.
  Then: оба решения — review: порог не зависит от возраста.
- **AC-MILEAGE-16** (REQ-MILEAGE-10). Given: две заявки с одинаковыми параметрами
  авто, суммы и оценочной стоимости (LTV 50 %); пробеги 399 999 км и 400 001 км.
  When: заявки оцениваются. Then: поле `ltv` в ответах одинаково; различаются только
  decision (approve / review) и approved_limit.

### Источники чисел

| Число | Источник |
|---|---|
| 400 000 км — порог, граница включительная («не больше» = ≤) | интервью, вопрос 2; intent, constraint 1 |
| 399 999 км — последнее значение до порога | граница порога 400 000 км; требование AC на границе — `docs/spec/README.md` |
| 400 001 км — первое значение за порогом | интервью, вопрос 2 |
| 450 000 км — пример из диапазона 400 001–500 000 | intent, constraint 3 (шкала); тот же пример — intent, раздел «Зачем» |
| 500 000 км — жёсткий потолок валидации | код: `backend/config/rules.php`, `max_mileage_km` |
| 500 001 км — первое значение за потолком | граница потолка 500 000 км |
| 0 км — трактовка пустой строки | код: `backend/src/Domain/ApplicationValidator.php` |
| HTTP 422 | код: `backend/src/Http/ApplicationController.php` |
| LTV 50 % / 75 % / 95 % — зоны approve / review / reject | пороги 60.0 / 85.0 — код: `backend/config/rules.php`, блок `ltv` |
| 2 и 15 лет — возраст авто в примере | синтетические примеры внутри допустимого диапазона 0–20 лет — код: `backend/config/rules.php`, `max_age_years` |

## 4. Open questions из intent

| Вопрос из intent | Статус |
|---|---|
| «иначе решение review» — только понижение approve → review или перекрытие любого решения? | закрыт: интервью, вопрос 1 — только понижение approve → review; отражено в REQ-MILEAGE-02, REQ-MILEAGE-03 |
| Ровно 400 000 км — approve или review? | закрыт: интервью, вопрос 2 — approve, граница включительная; REQ-MILEAGE-01, AC-MILEAGE-02 |

| Пустая строка `''` → 0 км — оставить? | закрыт: интервью, вопрос 4 — оставить; REQ-MILEAGE-06 |

| Порог единый или зависит от возраста/стоимости? | закрыт: интервью, вопрос 6 — единый; REQ-MILEAGE-09 |

Перенесённых открытых вопросов нет: все шесть закрыты ответами заказчика в интервью
`docs/intent/grill_MILEAGE.md`.
