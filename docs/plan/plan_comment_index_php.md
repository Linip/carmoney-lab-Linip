# План: комментарий в `backend/public/index.php`

Запрос: «короткий PHPDoc-блок перед `require dirname(__DIR__, 2) . '/vendor/autoload.php';`,
поясняющий, что это точка входа Slim-приложения» (вариант 1 из диалога).

## Файлы

Трогаем ровно один файл, остальные — нельзя:

| Файл | Что меняется |
|---|---|
| `backend/public/index.php` | Между строкой `use CarMoneyLab\AppFactory;` (текущая строка 5) и строкой `require dirname(__DIR__, 2) . '/vendor/autoload.php';` (текущая строка 7) вставляется PHPDoc-блок. Существующие строки, отступы и `declare(strict_types=1)` не трогаем. |

Никаких правок в `AppFactory`, `composer.json`, `phpunit.xml`, `backend/public/.htaccess`,
`Dockerfile`/`docker-compose.yml` — не требуется.

## Шаги

1. **Прочитать** `backend/public/index.php` (сделано в диалоге: 9 строк, блок `<?php` / `declare` /
   `use` / `require` / `AppFactory::create()->run();`).
2. **Вставить** PHPDoc-блок ровно между строкой 5 (`use CarMoneyLab\AppFactory;`) и строкой 7
   (`require dirname(__DIR__, 2) . '/vendor/autoload.php';`). Между `use` и блоком и между
   блоком и `require` — по одной пустой строке, как сейчас между `use` и `require`.
3. **Текст блока — кандидат** (заменить на формулировку заказчика, если будет):

   ```php
   /**
    * Точка входа HTTP-приложения (Slim): загрузка автозагрузчика и запуск AppFactory.
    */
   ```

   Этот текст не утверждён заказчиком дословно — помечен как кандидат (см. «Не хватает данных»).
4. **Проверить синтаксис**: `make lint` (= `php -l` по `backend/` и `tests/`). Должен пройти
   без ошибок: `/** */` в теле скрипта PHP игнорирует, на парсер не влияет.
5. **Не запускать** `make up` / `make seed` / `reset_db.sh` — комментарий поведения HTTP не
   меняет, отдельный функциональный прогон не требуется.

## Тесты

Новых PHPUnit-тестов не добавляем: правка — документационная, наблюдаемого поведения
(Slim-цикл, маршруты, JSON-ответы) не меняет.

Проверки, которые выполняем:

| Проверка | Команда | Ожидание |
|---|---|---|
| Синтаксис PHP | `make lint` | без ошибок |
| Smoke после вставки | `curl -sS http://localhost:8080/health` (если стек уже поднят) | `{"status":"ok","service":"carmoney-lab"}` — без изменений |

Граничные значения / Given–When–Then неприменимы (комментарий).

## Риски

1. **Стиль PHPDoc.** PHPDoc-блоки по конвенции PSR-5 / phpDoc ставят над функциями, методами,
   классами или первым блоком после `<?php`/`declare`. Блок «в середине» тела файла — между
   `use` и `require` — нестандартен. PHP-парсер и `php -l` это пропустят, но IDE / phpstan /
   psalm уровнем `error` могут выдать «PHPDoc has no associated target». Решение оставлено по
   букве запроса (перед `require`); если важна совместимость со static analysis — перенести
   блок сразу после `declare(strict_types=1);` и оформить как file-level docblock.
2. **Случайная правка кода.** Вставляем блок строго между строками 5 и 7. Никаких изменений
   в `declare`, `use`, самом `require` и `AppFactory::create()->run();` — иначе это уже не
   «просто комментарий».
3. **Кодировка / перевод строк.** Файл сейчас в UTF-8 без BOM, LF. Вставка должна
   сохранить тот же line-ending, иначе `git diff` покажет лишний «whitespace»-шум.
4. **Влияние на другие ветки/процессы.** Отсутствует: меняется только комментарий,
   `git grep` по сигнатурам не сломается, автотесты — зелёные.
5. **Конфликт с правилом «данные — синтетические».** Неприменимо: правка не вводит и не
   выводит данных.

## Не входит

- Любая правка `AppFactory::create()`, контейнера, маршрутов.
- Рефакторинг `index.php` в стиле bootstrap-класс с DI.
- Локализация комментария (en/ru) — на усмотрение исполнителя в рамках одного языка.
- Перенос блока в file-level docblock — отдельной задачей, если это понадобится.

## Не хватает данных

Чего в запросе не было и что нужно подтвердить у заказчика перед реализацией:

1. **Точная формулировка текста.** В плане дан только кандидат в одну строку
   (`Точка входа HTTP-приложения (Slim): загрузка автозагрузчика и запуск AppFactory.`).
   Заказчик может захотеть другой объём (одна строка vs. `@author`/`@since`-метаданные) или
   другой язык (файл сейчас без комментариев — однозначного прецедента ru/en нет).
2. **Место вставки — строго перед `require`, или допускается первым блоком после `<?php`?**
   Сейчас зафиксирован первый вариант (по букве запроса). Если важна совместимость со
   phpstan/psalm уровня «PHPDoc must have a target», нужно подтверждение переноса.
3. **Нужен ли отдельный file-level docblock (назначение файла, автор, версия) или только
   короткий маркер перед `require`?** Без ответа исполнитель ставит только маркер.
